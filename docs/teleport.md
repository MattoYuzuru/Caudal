# Доступность Teleport

Caudal проверяет публичный веб-прокси Teleport с сети, в которой работает сервер Caudal. Успешный замер подтверждает TLS и ожидаемый ответ `GET /webapi/ping`. Источник замера важен при сравнении с Chrome или `tsh` на устройстве владельца. [Документация Teleport о сети и TLS](https://goteleport.com/docs/reference/deployment/networking/)

## Настройка

Оператор задаёт `CAUDAL_TELEPORT_PROFILES` в окружении сервера. Доступно до восьми записей. У каждого профиля есть уникальный `id`, подпись `label` и публичный HTTPS origin `web_url`. Если Teleport слушает HTTPS на нестандартном порту, укажите его явно.

```sh
export CAUDAL_TELEPORT_PROFILES='[{"id":"lab","label":"Lab Teleport","web_url":"https://teleport.example.com:3080"}]'
```

Перезапустите Caudal, чтобы загрузить список. В карточке Teleport действие **Проверить** запускает замер, а ссылка открывает родной веб-интерфейс. Для входа и доступа к ресурсам действуют исходные SSO, MFA, права и срок действия сертификата Teleport. Сессия браузера оформляется на стороне Teleport. Для диагностики `tsh` проверьте состояние локального профиля через `tsh status`. [Документация Teleport для tsh](https://goteleport.com/docs/connect-your-client/tsh/)

## Сигнал проверки

| Состояние | Что установлено |
| --- | --- |
| `not_checked` | Caudal ещё не измерял доступность с момента запуска. |
| `reachable` | Прокси вернул ожидаемый JSON после проверенного TLS. |
| `unreachable` | Сохранён код сбоя DNS, сети, времени ожидания, TLS, запрета доступа или неожиданного HTTP-ответа. |

Caudal хранит в памяти время и длительность последней попытки, статус и версию из успешного ответа. Повторные вызовы в течение десяти секунд получают последний результат. Проверки обращаются только к адресам из операторской конфигурации. DNS-ответы с частными адресами и HTTP-перенаправления завершают замер. В запросе нет данных о сессиях, учётных данных и списке внутренних ресурсов.
