# Операции ассистента Caudal

В разделе «Подключения» виден каталог действий с целью, транспортом, методом и классом эффекта. Источник полномочий — конфигурация владельца control plane. DeepSeek может выбрать до четырёх ID из текущей области вопроса. Локальный режим также понимает короткие команды чтения, например «Проверь SSH на двух узлах» или «Проверь сигналы».

## Запуск и подтверждение

1. Ассистент создаёт план с неизменяемым набором операций. План привязан к сеансу владельца.
2. После подтверждения команды чтения выполняются параллельно. Настройка «Автоматически подтверждать чтение» позволяет выполнить такую группу сразу. Настройка по умолчанию выключена.
3. План с изменениями всегда ждёт отдельного подтверждения. `POST`, `PUT` и `PATCH` из HTTP-каталога считаются изменениями, `DELETE` — разрушительной операцией. В смешанном плане действия идут по порядку. Первый сбой или неизвестный результат прерывает следующие шаги.
4. В чате появляется результат с нумерованными строками. Ссылки вида `#run-<id>-L<номер>` ведут к строкам результата и восстанавливают его после перезагрузки в том же веб-сеансе. Кнопка «Спросить по результату» добавляет эти строки к следующему запросу.

Повторное подтверждение завершённого плана возвращает тот же результат. При тайм-ауте изменяющего HTTP-запроса эффект может оставаться неподтверждённым. Caudal не повторяет такой запрос автоматически. Планы и результаты хранятся в памяти до 30 минут, перезапуск завершает веб-сеанс. Серверный журнал хранит ID плана, ID выбранных операций и переходы. Ключи и вывод команд в журнал не попадают.

## Транспорты

| Транспорт | Что доступно |
| --- | --- |
| Сборщики | Свежесть последнего heartbeat, CPU, свободная память, диск и uptime. |
| Teleport HTTPS | Проверка `/webapi/ping` по настроенному профилю. Результат показывает доступность прокси из сети Caudal. |
| SSH | Фиксированный `/usr/bin/uptime` по выделенному ключу к известному хосту. Ключ хоста закреплён на стороне Caudal, логин выделен для диагностики. |
| `tsh` | Тот же запрос к заданному UUID ноды с машинной учётной записью Teleport, установленным клиентом и выданной администратором ролью. [Teleport Machine & Workload Identity](https://goteleport.com/docs/machine-workload-identity/machine-id/access-guides/ssh/) |
| HTTPS | Выбранный владельцем точный URL, метод и необязательное статическое JSON-тело до 4 КиБ. В квитанцию попадают HTTP-статус и время. |

Клиент HTTPS проверяет сертификат и публичность адреса из DNS, подключается к проверенному адресу и завершает запрос на ответе о перенаправлении. Регистрируйте только собственные или явно разрешённые конечные точки. Для HTTP GET и HEAD выбирайте интерфейсы без побочных эффектов. Указывайте URL без ключей и иных секретов, включая сегменты пути. В модели цель HTTP показана на уровне origin, в плане владельца виден полный настроенный адрес.

## Конфигурация оператора

Добавьте массив `CAUDAL_OPERATIONS` в `control.env`. После изменения перезапустите control plane. Пример формы конфигурации с условными адресами.

```json
[
  {
    "id": "site-health",
    "label": "Проверить сайт",
    "transport": "http",
    "target": "https://infra.example.com/healthz",
    "method": "GET"
  },
  {
    "id": "site-refresh",
    "label": "Перечитать статус",
    "transport": "http",
    "target": "https://infra.example.com/v1/refresh",
    "method": "POST",
    "body": {"scope": "status"}
  },
  {
    "id": "rack-uptime",
    "label": "Uptime сервера",
    "transport": "ssh",
    "target": "rack",
    "host": "rack.example.com",
    "port": 22,
    "login": "caudal_observer",
    "identity_file": "/run/credentials/caudal.service/rack-key",
    "known_hosts_file": "/run/credentials/caudal.service/rack-known-hosts"
  }
]
```

Для SSH строка known_hosts начинается с точного `target`. На целевом хосте ограничьте выделенный ключ `restrict` и forced command `/usr/bin/uptime`. Для systemd передавайте ключ и pin через `LoadCredential`. В записи `tsh` укажите `target` с UUID ноды, `proxy` с адресом и портом, `cluster`, `login` и `identity_file` машинной учётной записи. При истёкшем удостоверении операция завершится ошибкой. Веб-профиль Teleport можно проверять независимо.

Поле `node_id` можно задать для привязки операции к конкретному узлу Caudal по его неизменяемому ID. Без него операция доступна в области «Все узлы».

Ключ DeepSeek вводится в «Настройки → Ассистент» и остаётся в памяти открытого веб-сеанса. В чате можно выбрать провайдера, модель и глубину рассуждения. Явный запрос к DeepSeek передаёт вопрос, данные выбранной области, каталог доступных операций и строки результата при использовании кнопки разбора.
